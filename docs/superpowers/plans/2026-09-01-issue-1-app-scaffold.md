# Issue 1 App Scaffold Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Create a thin Android-first .NET MAUI solution with explicit UI, application, domain, and infrastructure boundaries plus a test project.

**Architecture:** Use the standard .NET MAUI single-project template under `src/GymTracker` plus a platform-neutral `src/GymTracker.Core` library for application contracts and composition. Retain MAUI platform targets for future iOS portability. Keep the initial app shell and composition root minimal; define no SQLite implementation, backend, account flow, or feature behavior in this issue.

**Tech Stack:** .NET SDK 10.0.400, .NET MAUI, C#, XAML, xUnit.

**Spec:** `docs/superpowers/specs/2026-09-01-issue-1-app-scaffold-design.md`

## Global Constraints

- Android is the first runnable target.
- The MAUI project retains iOS-compatible target structure for later enablement.
- UI, application, domain, and infrastructure concerns remain separately organized, with platform-neutral application contracts in `GymTracker.Core`.
- No backend, account flow, cloud service, SQLite implementation, or external health integration is introduced.
- The solution and test project must build together.
